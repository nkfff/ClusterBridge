ClusterBridge Detailed Tutorial (V2.0.0)

Last updated: 2026-10-23 17:18:59 +08:00

1) What ClusterBridge does

ClusterBridge bridges files between two SSH endpoints through your local computer. Data is streamed in memory and written to destination directly, without first saving a full copy on local disk.

2) Requirements checklist

  • Your computer can SSH/SFTP to both endpoints.
  • You have read permission on source path and write permission on destination path.
  • Your computer stays online and does not sleep during transfer.
  • Both clusters allow this relay pattern under their security policies.

3) Install and start

python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
python -m clusterbridge

4) Add SSH profiles

  1. Click Manage SSH connections.
  2. Click Add.
  3. Enter a connection name, SSH host, username, port, and default path.
  4. Enter the SSH password and click Save.
  5. The profile appears in both the Source and Destination selectors.

Connection metadata is stored in SQLite. Passwords are stored in the operating system keychain, not in the database. Use Edit to change metadata or replace a password; leave the password field blank to keep the existing keychain entry.

5) Queue multiple transfer tasks

  1. Open ClusterBridge.
  2. Add your clusters from Manage SSH connections if they are not already saved.
  3. Select Source and Destination (local or remote profile).
  4. Fill Source path and Destination path.
  5. Click Add task.
  6. Repeat to add more tasks.
  7. Click Start queued tasks.

Tasks run with bounded concurrency and independent resume behavior. If one task fails, completed tasks remain completed.

6) Path rules: file versus directory

V2.0.0 transfers one file per task. It does not yet recursively transfer a directory.

For a remote-to-local file transfer, use a complete file path on both sides:

Source profile:      Lab Cluster A
Source path:         /data/users/alice/sc_data/student.png
Destination:         This computer
Destination path:    /Users/alice/Downloads/student.png
  • Do not use a directory as the destination file path, such as /Users/alice/Downloads.
  • Do not select a source directory and expect recursive copying yet.
  • The destination parent directory must already exist or be creatable by the app.

7) Remote path rules

SFTP does not invoke a remote shell, so ~ is not expanded automatically. Use the absolute path returned by echo "$HOME" on the cluster. 

# Run on the cluster
echo "$HOME"

# Example
/home/alice/project/sample.h5ad

If the cluster uses a shared storage home, use that absolute path instead, for example /jinxianstor/jupyter/users/alice/project/sample.h5ad.

8) Resume behavior and safe retry

  • If destination file already exists and is smaller than source, transfer resumes from destination size.
  • You can rerun failed tasks by re-adding them and starting the queue again.
  • Do not modify source files during active transfers.

9) Typical scenarios

A. Cluster A → Cluster B

  • Source = profile cluster-a
  • Destination = profile cluster-b
  • Example file: /data/project/sample.h5ad → /scratch/project/sample.h5ad

B. Local → Cluster

  • Source = This computer
  • Destination = remote profile

C. Cluster → Local

  • Source = remote profile
  • Destination = This computer

10) Troubleshooting transfer failures

  • Auth failed: verify username/password in keychain and cluster SSH policy.
  • Path not found: verify source path and destination parent directory permissions.
  • Is a directory: replace the destination directory with a complete destination filename.
  • Source directory: select one file for the current V2.0.0 implementation.
  • Remote path with ~: replace it with the cluster user's absolute home path.
  • Task failed count: the status now includes the exception type and message for each failed task.
  • Very slow transfer: your home uplink can be the bottleneck in relay mode.
  • Transfer stops: check local sleep settings, VPN disconnects, and network drops.

11) Packaged app crash troubleshooting

If an older packaged app closes unexpectedly during transfer, download the latest release bundle. The current build avoids updating Qt widgets from the worker thread. Startup failures are written to: 

macOS/Linux: ~/.clusterbridge/logs/startup.log
Windows:     %USERPROFILE%/.clusterbridge/logs/startup.log

A transfer failure is different from a startup failure: transfer errors are shown in the task completion message with the exception type and message.

12) Security recommendations

  • Keep SSH host-key verification enabled.
  • Use least-privilege accounts for transfer-only workflows.
  • Store connection IDs/paths carefully; metadata can also be sensitive.
